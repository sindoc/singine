Active Governance Rules (8)

GOV-001 Response Transparency
Applies: Every time a human selects a response option
The selection MUST be recorded in the audit log with actor, timestamp, question ID, and chosen position before any action is dispatched. No action may begin without a confirmed audit entry.
GOV-002 Sync Action Accountability
Applies: Every synchronous action execution
Sync actions execute in the same thread as the response. Result (success or error) MUST be written to audit log and executions table. On failure the session continues; it does not abort remaining sync actions.
GOV-003 Async Action Queuing
Applies: Every asynchronous action dispatch
Async actions are enqueued in SQLite (status=pending). A singine worker polls and executes them independently. The enqueue operation is synchronous; the execution is not. Idempotency keys MUST be set on every async payload.
GOV-004 Human Task Escalation
Applies: Any action whose type is "human"
A human_tasks record is created (status=open) and a notification is sent (webhook or email). The session that triggered the task does NOT wait for resolution. Human tasks MUST be resolved within the configured SLA window (default: 48 h). Unresolved tasks after SLA are re-notified.
GOV-005 Logseq Sync Integrity
Applies: Any push or pull between local state and Logseq
A content hash of each page/block is stored before and after sync. On hash mismatch without an explicit commit, the sync is aborted and recorded as a conflict in audit log.
GOV-006 Knowledge Base Immutability
Applies: Any mutation to questions or response options
Questions and responses are versioned, not edited in place. The previous version is retained and marked inactive. All executions reference the version active at the time of the response.
GOV-007 Cost Visibility
Applies: Any response option with costLevel ≥ "high"
Before dispatching actions, the CLI MUST display the cost level and list all actions that will be triggered. An explicit confirmation prompt is required. Auto-mode (non-interactive) is not permitted for "critical" cost actions without a governance override flag.
GOV-008 silkpage Content Transformation Traceability
Applies: Any content transformation via silkpage
Input and output content hashes, the transformation template name, and silkpage version MUST be logged. Transformed content is stored in a staging area; it does not replace source until a commit step.
